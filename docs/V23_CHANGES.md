| G1 | **Slider drag path.** While a slider thumb moves, each frame is drawn by the GPU straight into a transient live canvas over `#mainImg`: no `toDataURL`/JPEG encode, no `<img>` decode, no overlay re-measure. ~140 ms after the last input one normal render encodes into `#mainImg.src`; the live canvas is removed only after that image has decoded (a newer drag frame always wins) and its backing store is set to 0x0. The -/+ buttons, presets, history, curves, colour mix and AI tools keep the V22 path; without WebGL2 the live path is skipped before any DOM work. ## Behaviour differences you may notice
- Background removal / AI mask edges: the matte is feathered at its own resolution and scaled up by the canvas (same feather-to-picture ratio as before), so edges are equivalent but not pixel-identical to V22.
- A photo that already has transparent areas keeps them through background removal (alpha is multiplied by the matte). V22 overwrote the alpha.
- Grain pattern differs per photo (seed re-rolled on upload) but is identical in preview and export for that photo. V22 used one fixed pattern for every photo.

## Limits you should know about
- No browser was available here: frame rate, real GPU/heap memory and the live-canvas alignment over the photo (frames, rounded corners, letterboxing) are NOT measured or rendered. The tests assert the code path (no encode while dragging, uploads once, canvases set to 0) through stub DOM/WebGL objects. Please check on a real device: slider drag with grain/vignette on a 12 MP photo, and the live canvas with a Frame active.
- The live canvas is pinned to the photo box when a drag starts; a window resize in the middle of a drag is corrected at the settle step (~140 ms later).
- Not done, by decision: the Pointer Events / `setPointerCapture` migration (targeted passive fixes only).
- Left in place on purpose (outside the approved list): the Premium modal markup and `closePremiumModal` (no opener now, but v22_test asserts its dialog markup); the OverlayManager engine (`add*`, render, `drawToCanvas`, history/export integration) - nothing in the UI can create an overlay any more, so removing the whole engine is a possible next step; write-only globals `lastFilterString`, `isProcessing`, `fullResCanvas/fullResCtx`.
- Unreferenced-name audit in `docs`/test titles is by static search; dynamic keys built from strings at runtime would not be seen (none exist today).
